# v4.11 工作台修复说明

基于 2026-09-07 审核时的现有文件修改，保留当时 index.html 已有的未提交内容。

## 已修复

- 语义评分改为可等待的最终结果，不再从异步回调直接渲染、保存和写回；任务取消后不能覆盖新报告或落库。
- 每日评分显示和导出使用同一结果；JSON 导出生成真正的 JSON，并过滤内部任务状态。
- 普通评分与视频转写共用任务锁，批量和完整日报各自管理任务；阻止重复点击。
- 批量最多并行 3 个文件，支持逐文件确认主播、日期、直播间和产品。所有文件完成后才发布 TOP1；失败项可重试，成功项不重复评分和存档。
- TOP1 同一天保存一份最终推荐；更新时合并同一天的旧重复记录。未满足推荐条件的不发布。
- 历史进步比较采用任务启动时的历史快照，排除本批新分；完整日报与文本评分标识不同类型，完整日报不混入文本历史基线。
- 本地新结果不会被无版本信息的飞书旧快照覆盖；有更新时间时比较版本。
- 数据表加载携带请求序号，旧请求不能覆盖新选择。
- 完整日报以同一对象提供展示、存档和同步；历史详情保存完整日报的能力/服化道分解。单次调用的语义豁免不会影响其他任务。
- 无有效画面、视觉接口失败或描述为空时不生成完整日报分数；重试复用已成功转写、抽帧和分析步骤。
- 手动确认后的主播等元数据优先，评分过程使用输入快照；日期采用日期控件并校验。
- HTTP 非成功状态不再显示服务健康；请求超时覆盖响应体读取，取消会中断在途请求。
- 渲染不再自动写飞书。按日报、附属表、周总结、月总结顺序同步，展示阶段状态并提供失败重试；已确认成功的阶段不重复提交。
- 本地存储失败在任务面板显示，并保留可导出的结果。
- 成功、信息和错误提示分别显示；提示放到右下角，任务面板提供取消、重试、导出及同步状态入口。

## 代码组织

- `app-core.js`：保留现有计算、报告渲染、服务兼容数据结构；评分入口委托 workflow。
- `semantic-core.js`：评分公式与语义证据应用逻辑保持原文件。
- `v4-shell.js`：导航、数据表、存档详情和可等待的语义适配器。
- `workflow.js`：任务归属、取消、最终提交、批量并发与同步队列。
- `v3/standard.js`、`v3/outfit.js` 不修改。

## 使用与后续边界

刷新 v4 页面后生效；若使用 file:// 打开，服务仍需按原配置启动。缓存版本号已更新。

本次完成前端修复，没有部署或修改云端接口，也没有迁移已有浏览器数据。同步重试状态和任务缓存保留在当前会话，刷新后会重置。真实服务连通性、实际模型返回和飞书字段映射仍需业务环境验收。

附属表服务的历史写入仍采用后端追加语义。如果服务已写入但响应丢失，前端不能确认远端是否成功；手动重试该阶段可能重复追加。需要后端支持 resultId 幂等键，才能实现跨断线/刷新的一次写入保证。前端已提供 resultId，并跳过当前会话中已确认成功的同步阶段。

localStorage 仍为存储介质；IndexedDB 迁移、跨设备任务恢复、后端幂等写入、评分规则中重复的 1.4 标准需要单独实施或确认业务口径。
